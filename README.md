# Мониторинг реферальной программы Uzum Tezkor

Раз в день робот GitHub Actions открывает https://referral.uzumtezkor.uz/, читает бонусы
за приглашённых курьеров по всем городам и видам транспорта и сохраняет их в историю.
Если что-то изменилось, в Telegram-группу приходит сообщение с кнопкой **«📊 Подробнее»**.
Кнопка открывает наш дашборд с историей, графиками и журналом изменений.

Компьютер для этого включать не нужно: всё работает на серверах GitHub.

- **Дашборд:** https://yandexeats.github.io/tezkor-referral-monitor/
- **Запуски робота:** https://github.com/YandexEats/tezkor-referral-monitor/actions

## Как это устроено

| Что | Где |
|---|---|
| Расписание и шаги робота | `.github/workflows/monitor.yml` |
| Чтение сайта (разбор JS-бандла) | `monitor/extract_bundle.js`, `monitor/scraper.py` |
| Запасной способ чтения (браузер Playwright) | `monitor/scraper.py` → `fetch_fallback` |
| Сравнение и журнал изменений | `monitor/diff.py` |
| Основная проверка | `monitor/check.py` |
| Отправка в Telegram | `monitor/notify.py`, `monitor/telegram.py` |
| Дашборд | `site/` (публикуется на GitHub Pages) |
| История (робот только дописывает, старое не удаляется) | `data/history.json`, `data/changes.json`, `data/last_check.json` |
| Тесты | `tests/` |

У сайта нет API: все цифры зашиты в JS-файл `/assets/index-<hash>.js`. Робот при каждой
проверке находит актуальный файл, вырезает из него объекты с городами и бонусами и
вычисляет их через Node.js. Имена переменных в файле меняются при каждой сборке сайта,
поэтому они нигде не прописаны жёстко.

Если основной способ не сработал, робот открывает сайт настоящим браузером (Playwright).
Если не сработали оба способа, история не меняется, в группу ничего не уходит,
администратору приходит предупреждение, а запуск помечается красным.

Найденное изменение робот перепроверяет через 2 минуты, чтобы не поднимать тревогу
из-за сайта, который выкладывается в эту минуту.

## Как поменять время проверки

1. Откройте файл `.github/workflows/monitor.yml` на GitHub и нажмите на карандаш (Edit).
2. Найдите строку `- cron: "0 5 * * *"`. Время в ней указано по **UTC**, а Ташкент = UTC+5.
   - `"0 5 * * *"` — каждый день в 10:00 по Ташкенту;
   - `"30 3 * * *"` — каждый день в 08:30 по Ташкенту;
   - `"0 5,13 * * *"` — дважды в день, в 10:00 и 18:00 по Ташкенту.
3. Нажмите **Commit changes**.

GitHub может запустить проверку с опозданием на 5–30 минут — это нормально.

## Как запустить проверку вручную

1. Откройте https://github.com/YandexEats/tezkor-referral-monitor/actions/workflows/monitor.yml
2. Нажмите **Run workflow**, оставьте `mode = check` и снова нажмите **Run workflow**.
3. Через 2–4 минуты появится зелёная галочка.

Режим `test_group_message` отправляет в группу одно сообщение с пометкой
«🧪 ТЕСТ, не реальное изменение», чтобы проверить кнопку. Кнопка открывает дашборд
с тестовыми данными (`?test=1`). Историю этот режим не читает и не меняет.

## Какие сообщения бывают

| Куда | Сообщение | Что значит |
|---|---|---|
| Группа | 🔔 Uzum Tezkor изменил реферальные бонусы | На сайте изменились суммы, условия, транспорт или города (изменение подтверждено повторной проверкой через 2 минуты) |
| Группа | 🧪 ТЕСТ, не реальное изменение | Ручная проверка кнопки, ничего не изменилось |
| Личка | ✅ Базовый снимок сохранён / Проверка: изменений нет, бот подключён | Бот подключён впервые, всё работает |
| Личка | ⚠️ Не удалось прочитать сайт, возможно изменилась структура | Авария, см. раздел ниже |
| Личка | ⚠️ Основной способ не сработал, данные получены запасным способом | Данные прочитаны, но основной способ стоит починить |

Если у вас установлен GitHub CLI, то же самое делается командой:

```bash
gh workflow run monitor.yml -R YandexEats/tezkor-referral-monitor
```

## Как поменять секреты (токен бота, ID группы)

Секреты хранятся только в GitHub (**Settings → Secrets and variables → Actions**):
`BOT_TOKEN`, `GROUP_CHAT_ID`, `ADMIN_CHAT_ID`. Ни в коде, ни в логах их нет.

- `GROUP_CHAT_ID` — ID группы (начинается с `-100`), туда приходят сообщения об изменениях бонусов.
- `ADMIN_CHAT_ID` — ваш **личный** ID (обычное число). В личку приходят служебные сообщения и предупреждения о поломках.

Поменять их можно так:
1. Напишите боту `/start` в личном чате. Добавьте бота в группу и напишите там `/start`
   (если бот не видит сообщение, напишите `/start@имя_бота`).
2. В папке проекта выполните `python get_chat_id.py` и вставьте токен. Скрипт покажет строки
   `ГРУППА: … → -100…` и `ЛИЧНЫЙ: … → …`.
3. Запустите `powershell -ExecutionPolicy Bypass -File .\set_secrets.ps1` и введите значения.
   Токен при вводе не отображается. ID группы без `-100` скрипт не примет. ID группы в поле личного ID — тоже.

Если секреты не заданы, робот работает как обычно, просто пишет в лог
«секреты не заданы — Telegram пропущен».

## Пришло предупреждение «Не удалось прочитать сайт»

Значит, сайт Uzum Tezkor изменился так, что робот не смог прочитать цифры
(или сайт был недоступен).

1. Откройте ссылку на запуск Actions из сообщения и посмотрите красный шаг «Проверка сайта».
2. Если сайт просто не открывался, ничего делать не нужно: завтра робот проверит снова.
   Можно также запустить проверку вручную (см. выше).
3. Если ошибка повторяется несколько дней, значит, изменилась структура сайта и нужно
   поправить `monitor/extract_bundle.js` (или запасной способ в `monitor/scraper.py`).
   После правки запустите тесты: `python -m pytest tests -v -s`.
4. Если в предупреждении написано «пропали города» и город действительно убрали из
   программы, запустите workflow вручную с галочкой `allow_city_removal`.

Предупреждение вида «Основной способ не сработал, данные получены запасным способом» —
это не авария: данные прочитаны, но основной способ стоит починить.

## Дашборд

- Работает на телефоне: его открывает кнопка из Telegram.
- Ссылка вида `?city=namangan&date=2026-11-16` открывает дашборд с фильтром по городу
  и прокручивает журнал до нужного изменения.
- По ссылке `?test=1` открываются **вымышленные** тестовые данные (`site/testdata/`)
  для проверки графиков. Настоящая история в них не попадает.
  Пересоздать их можно командой `python tests/make_testdata.py`.

## Тесты

```bash
python -m pytest tests -v -s
```

1. Разбор живого сайта точно воспроизводит эталонные бонусы.
2. Имитация изменения: полный путь от изменённого бандла до текста сообщения в Telegram (с поддельным Telegram).
3. Сломанный сайт (пустой бандл или сайт недоступен): только предупреждение администратору, история не тронута, код выхода ≠ 0.
4. Запасной способ (Playwright) даёт те же цифры.

## Почему робот не «засыпает»

GitHub отключает расписание в репозиториях без активности 60 дней. Робот при каждой
проверке обновляет `data/last_check.json` и делает коммит, поэтому репозиторий всегда активен.
